买完VPS第一件事往往是测速，但很多人直接跑一个speedtest就下结论"这机器网不行"，其实不同工具测的是完全不同的东西，选错工具很容易得出误导性的结论。

## speedtest-cli：测个大概的带宽

最常用也最简单，装好直接跑就出结果：

```bash
apt install speedtest-cli -y
speedtest-cli
```

结果里重点看Download、Upload、Ping这三项。这个工具测的是VPS到speedtest测速节点之间的带宽，**只能反映一个大概**——因为它连的是speedtest自己选的节点，不一定是你实际会访问的目标线路，跑出来数字很漂亮，不代表你访问国内网站也快。

## mtr：真正决定"国内访问快不快"的是回程路由

VPS本身带宽再大，如果回程线路绕路严重，从国内访问照样卡。这也是很多人"测速结果很好，网站还是打不开"的真正原因——他们只测了带宽，没测路由。

```bash
apt install mtr -y
mtr -r -c 100 目标IP
```

跑完看输出里经过的中间节点IP，能大致判断走的是什么线路——比如看到`59.43.x.x`开头的节点，说明走了CN2线路，回程质量会明显好于普通163骨干网。这个诊断对国内用户访问体验的参考价值，其实比单纯的带宽数字更大。

## iperf3：两台机器之间的精确带宽

speedtest-cli连的是第三方节点，如果想知道VPS到**自己本地网络**之间到底能跑多快，iperf3更准，因为是点对点直连测试，不经过中间商：

```bash
apt install iperf3 -y
```

VPS这边跑服务端：

```bash
iperf3 -s
```

本地这边发起测试：

```bash
iperf3 -c VPS的IP -t 30
```

记得VPS的防火墙要放行默认的5201端口，不然客户端连不上。这种方式测出来的数字，才是你自己实际能用到的真实带宽。

## 三个工具怎么选

不是三个都要跑一遍，看具体想确认什么：

只是想知道这台VPS带宽给的够不够、够不够对得起价格，speedtest-cli跑一次就够了；如果发现网站访问慢，怀疑是国内回程线路问题，mtr才是真正该用的诊断工具；如果需要一个精确到具体数字、能自己复现验证的带宽数据（比如向服务商反映带宽不达标时拿出证据），iperf3更合适。

## 测速结果好，网站还是慢

排查过路由和带宽都正常，网站访问依然卡，问题可能不在网络层面了——服务器配置本身、数据库查询效率、有没有开缓存，这些都会拖慢访问速度，光靠测网速工具查不出来。如果确认是网络延迟本身的问题，可以看看之前写的[Linux TCP/IP和BBR参数智能优化脚本](https://vpsjq.com/2025/11/30/linux-tcp-ip-%E5%92%8C-bbr-%E5%8F%82%E6%95%B0%E6%99%BA%E8%83%BD%E4%BC%98%E5%8C%96%E8%84%9A%E6%9C%AC/)，能改善不少场景下的传输体验；如果买VPS之前想先看看IP质量，避免买到被滥用过的脏IP，也可以参考[推荐几个IP工具](https://vpsjq.com/2025/05/06/%E6%8E%A8%E8%8D%90%E4%B8%80%E4%B8%AAip%E5%B7%A5%E5%85%B7/)那篇。
