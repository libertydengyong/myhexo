海外VPS有时候会遇到一个奇怪的问题：明明是日本、美国或者欧洲的服务器，但 Google、YouTube 这类服务访问的时候却被识别为中国IP，被重定向到中国版页面或者直接拒绝访问。这种情况理论上所有VPS都可能遇到，不只是某个特定地区的服务器。

usque 是一个专门处理这个问题的工具，通过修改服务器配置尽可能保护VPS的IP地理位置信息，避免被 Google 等服务误判为中国IP。一条命令安装：

\`\`\`bash
curl -sSL -o install_usque.sh https://gitlab.com/otisyang-group/usque-installer/-/raw/main/install_usque.sh && chmod +x install_usque.sh && sudo ./install_usque.sh
\`\`\`

安装完之后不需要额外配置，脚本会自动处理相关设置。这个工具的作用是尽可能保护IP，不能保证100%避免被误识别，但对于长期运行代理节点的服务器来说是一个值得加的保护措施。

对于纯IPv6 VPS来说，在安装 usque 之前需要先确保服务器能正常访问外网。如果你的纯IPv6 VPS还没有IPv4出口，可以先参考[又一个IPv6 only的小鸡添加v4的脚本](https://vpsjq.com/2026/04/30/2026-04-30-003/)，加好IPv4出口之后再运行 usque 安装命令，否则脚本下载可能会失败。在纯IPv6 VPS上用3x-ui搭节点的完整流程可以参考[纯IPv6 VPS用3x-ui搭建节点教程](https://vpsjq.com/2026/08/29/ipv6-vps-3xui-node/)。

被 Google 识别为中国 IP 的现象不只出现在某一类 VPS 上，搬瓦工、RN（RackNerd）这类知名服务商的服务器，甚至家宽都曾经出现过这个问题。被误识别之后最直接的表现是 Google 搜索打不开，或者被强制跳转到中国版页面，同时其他海外网站也可能受到影响，不只是 Google 一家。

这个问题的根源在于 IP 地址的地理位置数据库——MaxMind、IP2Location 这类数据库记录了每个 IP 段归属的国家和地区，Google 等服务依赖这些数据库来判断用户所在地区。如果数据库里某个 IP 段被错误地归类为中国，这个 IP 段下的所有服务器都会被误判，跟服务器实际在哪个数据中心没有直接关系。

数据库的更新有延迟，IP 段的归属信息也可能因为各种原因被错误记录，所以这个问题理论上任何海外 VPS 都可能遇到，只是概率不同。长期稳定运行代理节点的服务器，一旦遇到这个问题，节点会直接失效，用户连不上，排查起来也比较麻烦，因为服务器本身运行正常，问题出在 IP 地理位置识别这一层。

usque 通过修改服务器的相关配置，尽可能让 IP 地理位置数据库对这台服务器的识别结果保持准确，减少被误判为中国 IP 的概率。安装之后不需要手动验证，也没有明显的立竿见影的效果，更多是一种预防性的保护措施，适合长期跑节点的服务器提前部署。

如果你的 VPS 已经出现了被识别为中国 IP 的问题，除了安装 usque，也可以去 MaxMind 或者 IP2Location 的官网提交 IP 纠错申请，说明这个 IP 的实际归属地，等数据库更新之后问题通常会自动解决，但周期比较长，可能需要几周到几个月。
