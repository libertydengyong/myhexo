不少 VPS 默认安装完成以后，TCP 参数基本保持系统默认配置。

对于普通使用来说没有问题，但如果服务器部署网站、代理节点或者经常进行远程传输，适当优化 TCP 参数，通常能够改善网络传输效率。

bash <(curl -sL https://raw.githubusercontent.com/AiLi1337/TCP-Tuning-Simple-Version/main/TCP-Tuning-Simple-Version.sh)  

不过需要说明的是，TCP 调优并不是提高带宽，而是在现有线路基础上，通过优化 Linux 网络参数，提高连接效率以及减少部分高延迟环境下的网络损耗。

一般常见的 TCP 调优脚本会完成以下几项配置：

- 调整 TCP 缓冲区大小；
- 开启 TCP Fast Open；
- 优化 TCP KeepAlive；
- 调整队列算法（fq、fq_codel）；
- 修改网络连接参数；
- 根据系统情况开启 BBR。

需要注意的是，不同 Linux 系统之间默认参数并不完全相同。

例如 Debian、Ubuntu、Alpine 甚至不同版本内核，默认网络配置都会存在差异。

因此，不建议直接复制网上所有 sysctl 参数，而是根据当前系统和实际用途进行调整。

除了 TCP 参数之外，一台 VPS 的整体性能还受到很多因素影响，例如：

- CPU 性能；
- 内存大小；
- 磁盘读写速度；
- 网络线路质量；
- Linux 内核版本。

因此很多用户在部署完成以后，并不会只优化 TCP，而是一起完成系统初始化、网络优化以及安全配置。

优化完成以后，可以查看当前系统是否已经启用了对应参数。

例如查看当前拥塞控制算法：

```bash
sysctl net.ipv4.tcp_congestion_control
```

查看当前默认队列算法：

```bash
sysctl net.core.default_qdisc
```

查看当前 TCP Fast Open 配置：

```bash
sysctl net.ipv4.tcp_fastopen
```

如果服务器已经开启 BBR，也可以确认当前状态：

```bash
lsmod | grep bbr
```

不少用户会认为安装 TCP 调优脚本之后速度一定会明显提升。

实际上，影响网络速度最大的仍然是 VPS 本身线路。

TCP 调优主要改善的是网络传输效率和连接体验，对于高延迟线路或者跨境访问，通常会有一定帮助，但不会突破服务器本身带宽或者线路质量的限制。

对于长期运行的网站、代理节点以及远程管理服务器来说，合理调整 TCP 参数、保持系统更新，再结合稳定的网络线路，一般能够获得比较稳定的使用体验。
