面板部分假设已经按[S-UI面板搭建教程](/2025/11/17/s-ui面板搭建/)装好。这篇讲的是登录密码忘了怎么办，正好把[alireza0/s-ui安装与命令一览](https://vpsjq.com/2026/09/06/s-ui-alireza0-guide/)里提到过、但没展开讲的"更轻量的重置方式"补上。

## 先SSH进服务器，调出管理菜单

不管脚本安装还是Docker部署，密码问题都得先SSH进服务器处理，面板界面本身进不去是没法自助改密码的。脚本安装方式直接运行：

```bash
s-ui
```

会看到一个带编号的管理菜单，跟密码相关的是这三项：

- **5. Reset admin credentials to default** —— 重置成默认的 `admin` / `admin`
- **6. Set admin credentials** —— 直接设置成你指定的新用户名和密码
- **7. View admin credentials** —— 查看当前的管理员信息

## 直接设置新密码，不用先重置成默认值

大部分人第一反应是找"重置密码"的选项，但**这里更推荐直接用第6项 Set admin credentials**，一步到位设置成你想要的用户名和密码，不需要先变成默认凭据再登进去改一遍。选好这一项之后，命令行会提示你输入新的用户名和密码，输完立即生效，不用重启面板。

如果连用户名也不记得了，可以先用**第7项 View admin credentials**看一眼——不过这里有个容易搞错的地方：**这个功能只会显示用户名，密码那一栏不会显示明文，固定打印一行说明文字，告诉你密码是哈希存储、没法找回**。这是 S-UI 官方代码里就写死的行为，不是面板故障或者版本问题，源码里这个功能的密码输出永远是同一句"已哈希、不可找回"，不会因为你换了版本就能看到明文。想不起来当初设的密码是什么，唯一的办法就是设置一个新的，没有"找回旧密码"这条路。

## 什么情况下才用重置默认值

**第5项 Reset admin credentials to default** 会先跳出确认提示，明确写着"这会把管理员账号重置成用户名admin、密码admin，任何能访问到面板的人在你改密码之前都能登录进去"，需要手动输入 `y` 确认才会执行。这一步设计成需要手动确认，就是为了防止脚本被误触发导致面板瞬间变成"裸奔"状态。

正常情况下用第6项直接设置新密码就够了，不需要绕这一步。只有在你连第6项要求输入的交互流程都不方便操作（比如批量脚本化处理）的场景，才考虑先用第5项重置成默认值。**如果真的用了第5项，登录进去的第一件事就是立刻把用户名密码都改掉**，因为 admin/admin 是全世界都知道的默认凭据，面板端口和访问路径只要暴露在公网上，这段真空期就有被抢先登录的风险。

## 忘记的不是密码，是端口或者访问路径

如果你发现自己不是密码错了，而是压根不记得面板的端口号或者访问路径（WebBasePath）导致打不开面板，这跟密码问题是两回事，密码相关的菜单项帮不上忙。这种情况可以用管理菜单里的**第8项 Reset Panel Settings**把面板设置整体重置回默认值，代价是原来自定义的端口、访问路径都会被清空重来，需要重新设置。如果知道自己想改成什么值、不想直接重置成默认再改一遍，可以直接用第9项设置成指定的值，具体操作和改完必须重启这一步看[S-UI改面板端口和访问路径](https://vpsjq.com/2026/09/30/s-ui-change-port-webpath/)；访问路径改动会导致订阅链接失效这点，[S-UI面板订阅链接获取和客户端导入方法](https://vpsjq.com/2026/08/29/s-ui-subscription/)里也提到过。

如果是想彻底推倒重来、忘记密码只是原因之一，那可以考虑[alireza0/s-ui文章](https://vpsjq.com/2026/09/06/s-ui-alireza0-guide/)里讲的删库重装，但记得先按那篇里说的备份好 `db/` 目录，删库是不可逆操作，能用密码重置解决的问题不建议直接删库。
