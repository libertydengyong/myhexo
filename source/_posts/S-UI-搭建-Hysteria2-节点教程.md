Hysteria2 是近两年在自建节点圈子里热度很高的协议，底层基于 QUIC，抗丢包能力强，在弱网环境下的体验通常比传统 TCP 类协议更稳定。S-UI 作为轻量级面板，对 Hysteria2 的支持比较完整，入站参数、证书这些都能在网页里直接配置，不需要手动改配置文件；端口跳跃这个进阶功能目前面板还没有原生支持，具体现状下面会单独说明。这篇教程记录一下用 S-UI 从零搭建 Hysteria2 节点的完整流程。如果你还没装过面板，可以先看一下 [S-UI面板搭建教程](/2025/11/17/s-ui%E9%9D%A2%E6%9D%BF%E6%90%AD%E5%BB%BA/) 把基础环境铺好，这篇文章默认面板已经装好。

## 准备工作

搭建之前先确认几件事：

- VPS 配置：1 核 CPU、512MB 内存基本够用，Hysteria2 本身对硬件要求不高，主要看带宽是否充足。
- 系统版本：Debian 11/12、Ubuntu 20.04 及以上都可以，CentOS 也支持，但社区教程大多以 Debian 为例。
- 端口：Hysteria2 走的是 UDP，防火墙和云厂商的安全组要提前放行对应端口，否则装完连不上。
- 域名（可选）：如果打算用正式证书而不是自签证书，需要提前把域名解析到 VPS 的 IP。

## 安装 S-UI 面板

如果这台机器还没有装面板，先执行安装命令：

```bash
bash <(curl -Ls https://raw.githubusercontent.com/alireza0/s-ui/master/install.sh)
```

安装完成后脚本会输出面板访问地址、端口和登录账号密码，记下来，浏览器打开后台。首次登录建议先改掉默认密码，再进行下面的入站配置。

## 创建 Hysteria2 入站

进入面板的入站管理页面，点新建入站：

1. 入站类型选择 `Hysteria2`。
2. 监听端口自定，比如 `44444`，记得在安全组里放行这个 UDP 端口。
3. 带宽参数（上行/下行）按 VPS 实际带宽填写，太高会导致拥塞控制失效，一般按实际带宽的 70%~80% 填比较稳。
4. 混淆（obfs）可以开启 `salamander`，能一定程度提升抗封锁能力，不是必须项。
5. 保存后面板会自动生成该入站对应的密码，记下来后面用不上单独填，导出订阅时会自带。

如果你想对比一下 Hysteria2 和其他协议的差异，可以参考 [TUIC 节点搭建教程](/2026/09/06/s-ui-tuic/)，两者都是基于 QUIC 的协议，但拥塞控制算法和实现细节不一样，实际体验会因线路而异。

## 配置 TLS 证书

Hysteria2 强制走 TLS，证书这块有两种常见做法：

**方式一：自签证书**

不需要域名，面板里直接生成自签证书即可，适合临时用或者自己测试。客户端连接时需要把 `insecure`（跳过证书验证）选项打开，不然会握手失败。

**方式二：正式证书**

如果有域名，可以在面板证书管理里用 acme 自动申请 Let's Encrypt 证书，申请前确保域名已经解析到 VPS IP，且 80/443 端口没被其他服务占用。用正式证书的好处是客户端不用开 `insecure`，安全性和兼容性都更好一些。

## 端口跳跃（可选）

Hysteria2 支持端口跳跃，简单说就是让流量在一段端口范围内随机跳转，能在一定程度上规避针对单端口的流量识别和限速。需要说明的是，目前 S-UI 面板的入站设置里还没有直接提供这个配置项（GitHub 上有相关的功能请求还在等待合并），并不是在面板高级设置里填一下端口范围就能自动生效，实际要做需要在服务器防火墙层面手动配置端口转发规则。这个功能不是必需项，普通场景可以先跳过；如果确实需要，具体操作方法可以参考 [S-UI 端口跳跃配置教程](/2026/09/06/s-ui-port-hopping/)。

## 生成订阅并导入客户端

回到用户管理页面：

1. 新建用户，名字随便起，方便识别就行。
2. 入站标签选择刚才建好的 Hysteria2 入站。
3. 保存后点击该用户，复制生成的节点链接或订阅地址。

把链接导入支持 Hysteria2 协议的客户端（比如 NekoBox、Clash Verge 等主流客户端目前都已经支持），连接后可以打开一个 IP 查询网站，确认出口 IP 是否变成了 VPS 的 IP，没问题就说明节点搭建成功了。

## 常见问题

**如何搭建 Hysteria2 节点？**
核心步骤就是装好 S-UI 面板、新建 Hysteria2 入站、配置证书、生成用户订阅这四步，具体参数可以参照上文，大部分卡壳的地方都出在防火墙没放行 UDP 端口或者证书没配对。

**Hysteria2 可以使用哪些机场？**
这里说的是自建场景，跟第三方机场是两回事。如果你是想直接用现成的 Hysteria2 节点而不是自建，需要找明确支持该协议的服务商，具体选择因人而异，这篇教程主要讲自己动手搭建。

**TUIC 和 Hysteria2 节点有什么区别？**
两者都基于 QUIC，思路类似，主要差异在拥塞控制算法和握手细节上，实际表现跟具体线路关系很大，没有绝对谁更好，建议都试一下再决定用哪个，参考前面提到的 [TUIC 节点搭建教程](/2026/09/06/s-ui-tuic/)。

**S-UI 和 3x-ui 哪个好？**
S-UI 更轻量，界面和配置逻辑相对简洁，对新协议（比如 Hysteria2、TUIC）的支持更新也比较快；3x-ui 功能更全、社区教程更多，胜在资料丰富、上手门槛低。两者选哪个更多是习惯问题，都能实现同样的功能。

搭建完成之后，如果还想在这台机器上叠加其他协议做多用户管理，或者把这台机器做成中转落地架构，可以参考 [S-UI 中转落地搭建教程](/2026/01/11/s-ui%E4%B8%AD%E8%BD%AC%E8%90%BD%E5%9C%B0%E6%90%AD%E5%BB%BA%E6%95%99%E7%A8%8B/)，思路是把入口和出口拆到两台机器上，进一步提升线路的灵活性。
